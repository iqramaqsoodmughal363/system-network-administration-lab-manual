CHAPTER 1: The Foundation — Server Environment & OS Setup

1. Concept & Theory

Server Environment: Server Operating Systems (Windows Server, Ubuntu Server, RHEL) are designed to provide continuous network services (DNS, DHCP, Active Directory) to client devices. Unlike Desktop OS, Server OS is optimized for high background service loads, remote management, and strict access controls.

Storage Allocation: / (Root) holds all core files; /boot contains kernel and bootloader files; swap acts as virtual memory when physical RAM is exhausted.

2. Step-by-Step Command Execution & File System Actions

# 1. Network Interface & IP Checking
ip a
-> [ACTION: Screen par sabhi network interfaces (e.g., eth0, lo) aur unke IPs DISPLAY karta hai]

ip link set eth0 up
-> [ACTION: eth0 network card ko ENABLE/TURN ON karta hai]

ip link set eth0 down
-> [ACTION: eth0 network card ko DISABLE/TURN OFF karta hai]

# 2. Static IP Setup (Netplan File Editing)
sudo nano /etc/netplan/01-netcfg.yaml
-> [ACTION: Netplan configuration FILE OPEN karke EDIT karta hai]

# File contents:
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: no
      addresses: [192.168.1.10/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]

sudo netplan apply
-> [ACTION: New network settings ko System memory mein APPLY aur SAVE karta hai]

# 3. Connectivity Verification
ping -c 4 192.168.1.1
-> [ACTION: Gateway ko 4 test packets SEND karke connection VERIFY karta hai]

traceroute -n 8.8.8.8
-> [ACTION: Destination tak jaane wale raste ke tamaam Routers DISPLAY karta hai]
Viva Q1: Why do servers require static IP addresses?
Ans: Servers provide continuous network services. Dynamic IP changes break client requests, DNS records, and active connections.
Viva Q2: What is the purpose of Swap partition?
Ans: Swap serves as secondary memory on hard disk space when physical RAM is completely filled.

CHAPTER 2: Linux Boot Management, Process Control & Monitoring

1. Concept & Theory

Systemd Init System: Systemd manages system startup services via targets (e.g., multi-user.target replaces traditional Runlevel 3, graphical.target replaces Runlevel 5).

Process States: Running (R), Sleeping (S), Stopped (T), and Zombie (Z). Processes are assigned a Process ID (PID) and priority levels (Nice values from -20 to 19).

2. Step-by-Step Command Execution & File System Actions

# 1. Boot Target Management
systemctl get-default
-> [ACTION: Current default boot mode DISPLAY karta hai]

sudo systemctl set-default multi-user.target
-> [ACTION: Default boot target file KO MODIFY karke Command-Line Interface (CLI) mode set karta hai]

# 2. Process Identification & Termination
ps aux | grep apache2
-> [ACTION: Running processes LIST karta hai aur "apache2" ko FILTER karke screen par dikhata hai]

kill -9 1234
-> [ACTION: PID 1234 wale running process ko FORCEFULLY KILL/DELETE kar deta hai]

pkill -f nginx
-> [ACTION: "nginx" naam ke tamaam running processes ko ek sath TERMINATE kar deta hai]

# 3. Process Priority Adjustment
nice -n 10 ./backup_script.sh
-> [ACTION: Script ko LOWER PRIORITY (+10) ke sath LAUNCH/EXECUTE karta hai]

renice -n -5 -p 5678
-> [ACTION: Running PID 5678 ki priority BADHA (+5 se -5) kar fast processing ke liye UPDATE karta hai]

# 4. System Health Check
top
-> [ACTION: System resources (CPU, RAM, Processes) ko REAL-TIME MONITORING mode mein OPEN karta hai]
Viva Q1: What is a Zombie Process?
Ans: A process that has completed execution but its entry remains in the process table because its parent process hasn't read its exit status.
Viva Q2: What is the highest priority nice value in Linux?
Ans: -20 is the highest priority, while +19 is the lowest priority.

CHAPTER 3: Packet Filtering & Network Traffic Security

1. Concept & Theory

IPTables Architecture: Uses Tables (Filter, NAT, Mangle) and Chains (INPUT, OUTPUT, FORWARD) to inspect and filter network packets. Operations include ACCEPT (pass packet), DROP (discard packet quietly), and REJECT (discard and notify sender).

2. Step-by-Step Command Execution & File System Actions

# 1. Flush & Reset Rules
sudo iptables -F
-> [ACTION: Firewall memory se pehle se mojud tamaam filtering rules KO DELETE/CLEAR karta hai]

# 2. Set Default Chain Policies
sudo iptables -P INPUT DROP
-> [ACTION: Default Policy UPDATE karta hai: Tamam incoming traffic BLOCK ho jaye gi]

sudo iptables -P OUTPUT ACCEPT
-> [ACTION: Default Policy UPDATE karta hai: Tamam outgoing traffic ALLOW ho jaye gi]

# 3. Add Access Rules
sudo iptables -A INPUT -i lo -j ACCEPT
-> [ACTION: Loopback interface (Localhost) ka traffic ALLOW karne ka RULE ADD karta hai]

sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
-> [ACTION: SSH Service (Port 22) par incoming traffic ALLOW karne ka RULE ADD karta hai]

sudo iptables -A INPUT -s 192.168.1.50 -j DROP
-> [ACTION: Specific IP (192.168.1.50) ke saare packets KO BLOCK/DISCARD karne ka RULE ADD karta hai]

# 4. List Active Rules
sudo iptables -L -v -n --line-numbers
-> [ACTION: Tamaam active firewall rules ko Line Numbers ke sath DISPLAY karta hai]

sudo iptables -D INPUT 3
-> [ACTION: INPUT chain se Rule Number 3 KO DELETE/REMOVE kar deta hai]
Viva Q1: Difference between DROP and REJECT targets in IPTables?
Ans: DROP silently discards packets without notifying the sender. REJECT drops the packet and returns an ICMP "Destination Unreachable" error.
Viva Q2: Which table handles NAT in IPTables?
Ans: The NAT table, using PREROUTING and POSTROUTING chains.

CHAPTER 4: Automation — System Administration Bash Scripting

1. Concept & Theory

Bash Scripting: Automates system administrative routines such as system backup, resource monitoring, log auditing, and user creation. Uses control structures (if/else, for loops) and system binaries.

2. Step-by-Step Command Execution & File System Actions

# 1. Script File Creation
nano sys_monitor.sh
-> [ACTION: "sys_monitor.sh" naam ki NEW FILE CREATE karke EDIT mode mein OPEN karta hai]

# File Contents:
#!/bin/bash
LOG_FILE="/var/log/sys_audit.log"
THRESHOLD=80

echo "=== System Check: $(date) ===" >> $LOG_FILE
DISK_USAGE=$(df / | awk 'NR==2 {print $5}' | sed 's/%//')

if [ "$DISK_USAGE" -gt "$THRESHOLD" ]; then
    echo "CRITICAL: High Disk Usage (${DISK_USAGE}%)" >> $LOG_FILE
else
    echo "Disk Usage Normal: ${DISK_USAGE}%" >> $LOG_FILE
fi

# 2. File Permissions Setup
chmod +x sys_monitor.sh
-> [ACTION: File ke permissions MODIFY karke usko EXECUTABLE FILE bana deta hai]

# 3. Execution
./sys_monitor.sh
-> [ACTION: Bash script KO EXECUTE/RUN karta hai aur output log file mein SAVE karta hai]

# 4. View Created Log File
cat /var/log/sys_audit.log
-> [ACTION: Audit Log File ke contents ko screen par DISPLAY karta hai]
Viva Q1: What is the purpose of the Shebang (`#!/bin/bash`) line?
Ans: It specifies the absolute interpreter path required to execute the commands within the script.
Viva Q2: How to schedule a script to run daily at 2 AM?
Ans: Add a cron job entry in crontab -e: 0 2 * * * /path/to/sys_monitor.sh.

CHAPTER 5: Infrastructure Sharing — Network File Servers (NFS, Samba, FTP)

1. Concept & Theory

Network File System (NFS): Native Linux-to-Linux distributed file protocol.

Samba Server: Implements Server Message Block (SMB/CIFS) protocols to share files and printers seamlessly between Linux and Windows operating systems.

FTP (Very Secure FTP Daemon): Client-server protocol used to transfer files across TCP networks.

2. Step-by-Step Command Execution & File System Actions

# 1. NFS Server Configuration
sudo mkdir -p /srv/nfs_share
-> [ACTION: Storage ke liye "/srv/nfs_share" DIRECTORY/FOLDER CREATE karta hai]

sudo chown nobody:nogroup /srv/nfs_share
-> [ACTION: Shared folder ke OWNER permissions CHANGE karke public access set karta hai]

sudo nano /etc/exports
-> [ACTION: NFS Config FILE EDIT karta hai aur share paths ADD karta hai]
# Content: /srv/nfs_share 192.168.1.0/24(rw,sync,no_subtree_check)

sudo exportfs -a
-> [ACTION: Exports file ki new configuration ko RE-EXPORT/LOAD karta hai]

# 2. Samba Server Configuration
sudo mkdir -p /srv/samba_share
-> [ACTION: Samba sharing ke liye NEW FOLDER CREATE karta hai]

sudo smbpasswd -a john
-> [ACTION: Existing Linux user "john" ko Samba User Database mein ADD karta hai aur PASSWORD set karta hai]

sudo systemctl restart smbd
-> [ACTION: Samba Daemon Service KO RESTART karta hai taake naye shares ACTIVE ho jayein]
Viva Q1: Which protocol enables Linux to share files with Windows OS?
Ans: Samba (using the SMB/CIFS protocol).
Viva Q2: Difference between NFS and Samba?
Ans: NFS is lightweight and optimized for Unix/Linux hosts; Samba provides cross-platform file and print sharing with Active Directory integration capabilities.

CHAPTER 6: Core Network Services — DNS, DHCP & Apache Web Server

1. Concept & Theory

DHCP (Dynamic Host Configuration Protocol): Automates IP address assignment using the DORA process (Discover, Offer, Request, Acknowledge).

DNS (Domain Name System): Maps hostnames to IP addresses using resource records (A, PTR, CNAME, MX).

Apache HTTP Server: Hosts web content and processes HTTP requests on Port 80.

2. Step-by-Step Command Execution & File System Actions

# 1. DHCP Configuration File Update
sudo nano /etc/dhcp/dhcpd.conf
-> [ACTION: DHCP Configuration FILE EDIT karta hai]
# Add:
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.100 192.168.1.200;
  option routers 192.168.1.1;
  option domain-name-servers 192.168.1.10;
}

sudo systemctl restart isc-dhcp-server
-> [ACTION: DHCP Service KO RESTART karke automatic IP pool ALLOCATE karna SHURU karta hai]

# 2. BIND9 DNS Zone File Setup
sudo nano /etc/bind/db.enterprise.local
-> [ACTION: Forward DNS Lookup Zone FILE CREATE/EDIT karta hai]
# Add:
$TTL 604800
@ IN SOA ns1.enterprise.local. admin.enterprise.local. ( 2 604800 86400 2419200 604800 )
@ IN NS ns1.enterprise.local.
ns1 IN A 192.168.1.10
www IN A 192.168.1.20

# 3. Apache Virtual Host Setup
sudo mkdir -p /var/www/enterprise
-> [ACTION: Web content ke liye DocumentRoot FOLDER CREATE karta hai]

echo "<h1>Welcome to Enterprise Web</h1>" | sudo tee /var/www/enterprise/index.html
-> [ACTION: New Web Page File "index.html" CREATE karta hai aur text INJECT karta hai]

sudo a2ensite enterprise.conf
-> [ACTION: Apache site configuration link ENABLE/ACTIVATE karta hai]

sudo systemctl reload apache2
-> [ACTION: Apache Server KO RELOAD karta hai bina clients ko disconnect kiye]
Viva Q1: Explain the DHCP DORA process.
Ans: Discover (client broadcast), Offer (server response), Request (client selection), Acknowledge (server confirms lease).
Viva Q2: What is the purpose of a DNS PTR record?
Ans: PTR (Pointer) records map an IP address to a Domain Name (Reverse DNS Lookup).

CHAPTER 7: Windows Server Administration & Active Directory DS

1. Concept & Theory

Active Directory Domain Services (AD DS): A centralized directory service storing domain objects (users, groups, computers, printers) and controlling authentication and authorization policies across a network.

Logical Structure: Objects -> Organizational Units (OUs) -> Domains -> Trees -> Forest.

2. Step-by-Step Command Execution & File System Actions (PowerShell)

# 1. Install AD DS Role
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
-> [ACTION: System mein Active Directory Roles aur Management Consoles INSTALL/WRITE karta hai]

# 2. Promote Server to Domain Controller (Create Forest)
Install-ADDSForest -DomainName "enterprise.local" -DomainNetbiosName "ENTERPRISE" -Force:$true
-> [ACTION: Database CONVERT karta hai, DNS Server INSTALLL karta hai, aur Server ko Domain Controller BANA deta hai]

# 3. Organizational Unit (OU) & User Management
New-ADOrganizationalUnit -Name "IT_Dept" -Path "DC=enterprise,DC=local"
-> [ACTION: Active Directory Database ke andar "IT_Dept" naam ka NEW CONTAINER/OU CREATE karta hai]

New-ADUser -Name "JohnDoe" -SamAccountName "jdoe" -UserPrincipalName "jdoe@enterprise.local" -Path "OU=IT_Dept,DC=enterprise,DC=local" -Enabled $true
-> [ACTION: IT_Dept OU ke andar "JohnDoe" naam ka NEW USER ACCOUNT CREATE karta hai]

New-ADGroup -Name "IT_Admins" -GroupScope Global -GroupCategory Security
-> [ACTION: Active Directory mein Global Security GROUP CREATE karta hai]

Add-ADGroupMember -Identity "IT_Admins" -Members "jdoe"
-> [ACTION: User "jdoe" ko "IT_Admins" Group ke andar ADD/MEMBER BANA deta hai]
Viva Q1: Difference between Group and Organizational Unit (OU)?
Ans: An OU is a container used to delegate administrative permissions and apply Group Policy Objects (GPOs). A Group is used to grant access permissions to resources.
Viva Q2: What is the FSMO role in AD DS?
Ans: Flexible Single Master Operations roles are specialized tasks assigned to specific DCs to prevent database update conflicts.

CHAPTER 8: Managed Switches, Access Points & VLAN Trunking

1. Concept & Theory

VLAN (Virtual Local Area Network): Logically segments physical switch ports into distinct broadcast domains to increase security and reduce network congestion.

Switch Port Modes:

  • Access Port: Carries untagged traffic for a single VLAN.
  • Trunk Port: Carries tagged traffic for multiple VLANs using IEEE 802.1Q encapsulation.

2. Step-by-Step Cisco CLI Command Execution

# 1. Basic Switch Initialization
Switch> enable
-> [ACTION: User Exec Mode se Privileged EXEC Mode mein ENTER karta hai]

Switch# configure terminal
-> [ACTION: Global Configuration Mode OPEN karta hai]

Switch(config)# hostname SW-CORE-01
-> [ACTION: Switch Device Hostname CHANGE karke "SW-CORE-01" UPDATE karta hai]

# 2. VLAN Creation & Port Assignment
SW-CORE-01(config)# vlan 10
-> [ACTION: Switch Memory mein VLAN ID 10 CREATE karta hai]

SW-CORE-01(config-vlan)# name Sales
-> [ACTION: VLAN 10 ko "Sales" NAME ASSIGN karta hai]

SW-CORE-01(config)# interface range fastEthernet 0/1 - 5
-> [ACTION: Port 1 se 5 tak MULTIPLE PORTS SELECT karta hai]

SW-CORE-01(config-if-range)# switchport mode access
-> [ACTION: Selected ports ko ACCESS MODE par SET karta hai]

SW-CORE-01(config-if-range)# switchport access vlan 10
-> [ACTION: Selected ports ko VLAN 10 ke andar ASSIGN/ADD karta hai]

# 3. 802.1Q Trunk Port Configuration
SW-CORE-01(config)# interface gigabitEthernet 0/1
-> [ACTION: Uplink Gigabit Port SELECT karta hai]

SW-CORE-01(config-if)# switchport mode trunk
-> [ACTION: Port ko TRUNK MODE par MODIFY karta hai (Multi-VLAN traffic handler)]

SW-CORE-01(config-if)# switchport trunk allowed vlan 10,20
-> [ACTION: Trunk Port par sirf VLAN 10 aur 20 traffic ALLOW karne ki PERMISSION SET karta hai]
Viva Q1: What framing standard is used for Trunk links?
Ans: IEEE 802.1Q standard, which inserts a 4-byte VLAN tag into Ethernet frames.
Viva Q2: Can hosts on VLAN 10 talk to hosts on VLAN 20 directly on a Layer 2 switch?
Ans: No, traffic between different VLANs requires a Layer 3 device (Router or Layer 3 Switch).

CHAPTER 9: WAN Networking & Routing Protocols (Static, RIP, IGRP)

1. Concept & Theory

Static Routing: Manually defined routes entered into the routing table. Highly secure, low CPU overhead, but unsuitable for dynamic, expanding topologies.

RIP v2 (Routing Information Protocol): Distance-vector dynamic protocol using Hop Count as a metric (maximum 15 hops). Sends updates via multicast address 224.0.0.9.

2. Step-by-Step Cisco CLI Command Execution

# 1. Interface IP Configuration
Router(config)# interface serial 0/0/0
-> [ACTION: Serial WAN Interface SELECT karta hai]

Router(config-if)# ip address 10.0.0.1 255.255.255.252
-> [ACTION: WAN Interface par IP Address aur Subnet Mask WRITE/SET karta hai]

Router(config-if)# no shutdown
-> [ACTION: Interface State UP/ENABLE karta hai]

# 2. Static Route Configuration
Router(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2
-> [ACTION: Destination Network 192.168.20.0 tak pahunchne ke liye MANUAL ROUTE ADD karta hai via Next-Hop IP 10.0.0.2]

# 3. Dynamic Routing Configuration (RIP v2)
Router(config)# router rip
-> [ACTION: Router Engine mein RIP Routing Protocol Process ENABLE/START karta hai]

Router(config-router)# version 2
-> [ACTION: Protocol ko Classless RIP Version 2 par SET karta hai]

Router(config-router)# no auto-summary
-> [ACTION: Automatic Classful route summarization KO DISABLE/OFF karta hai]

Router(config-router)# network 192.168.10.0
Router(config-router)# network 10.0.0.0
-> [ACTION: Local directly connected networks ko RIP advertisement LIST mein ADD karta hai]

# 4. Routing Table Verification
Router# show ip route
-> [ACTION: Router ka Routing Table DISPLAY karta hai (Static 'S', RIP 'R' routes)]
Viva Q1: What is the maximum hop count for RIP protocol?
Ans: Maximum hop count is 15. A hop count of 16 indicates the destination network is unreachable.
Viva Q2: What metric does RIP use to select the best path?
Ans: Hop Count (number of routers traversed).

CHAPTER 10: Router Security — Access Control Lists (Standard & Extended)

1. Concept & Theory

Access Control Lists (ACLs): Sequential filters applied to router interfaces to permit or deny packets based on criteria.

  • Standard ACLs (1-99 / 1300-1999): Filter packets based strictly on Source IP Address. Must be placed as close to the destination as possible.
  • Extended ACLs (100-199 / 2000-2699): Filter based on Source IP, Destination IP, IP Protocol (TCP/UDP), and Port Numbers. Must be placed as close to the source as possible.

2. Step-by-Step Cisco CLI Command Execution

# 1. Standard ACL (Block Host 192.168.1.50)
Router(config)# access-list 10 deny host 192.168.1.50
-> [ACTION: Specific Host IP ko BLOCK karne ka Standard ACL Rule CREATE karta hai]

Router(config)# access-list 10 permit any
-> [ACTION: Baki tamam IP addresses ko PERMIT/ALLOW karne ka Rule ADD karta hai]

Router(config)# interface fastEthernet 0/0
Router(config-if)# ip access-group 10 out
-> [ACTION: Rule 10 ko Output Interface par APPLY/ACTIVATE karta hai]

# 2. Extended ACL (Allow SSH, Block HTTP)
Router(config)# ip access-list extended SECURE_ACL
-> [ACTION: "SECURE_ACL" naam ka Extended ACL Mode OPEN/CREATE karta hai]

Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.5 eq 22
-> [ACTION: Subnet se Web Server tak SSH Traffic (Port 22) ALLOW karne ka Rule WRITE karta hai]

Router(config-ext-nacl)# deny tcp 192.168.1.0 0.0.0.255 host 10.0.0.5 eq 80
-> [ACTION: Subnet se Web Server tak Web Traffic (Port 80 HTTP) BLOCK/DENY karne ka Rule WRITE karta hai]

Router(config-ext-nacl)# permit ip any any
-> [ACTION: Baki tamaam IP traffic ko ALLOW karta hai (Overrides default implicit deny)]

Router(config)# interface fastEthernet 0/1
Router(config-if)# ip access-group SECURE_ACL in
-> [ACTION: Created Extended ACL ko Input Interface par APPLY/BIND kar deta hai]

# 3. ACL Verification
Router# show access-lists
-> [ACTION: System mein configured saare ACL rules aur unke packet match counts DISPLAY karta hai]
Viva Q1: Where should Standard ACLs be placed?
Ans: As close to the destination network as possible.
Viva Q2: What is the implicit rule at the end of every ACL?
Ans: An invisible deny ip any any rule that blocks all unmatched traffic.
